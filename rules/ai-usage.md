# Utilisation responsable de l'IA de développement

- Considérer les réponses, le code et les explications générés comme des propositions à vérifier.
- Lire le code existant et les consignes du dépôt avant de proposer une modification.
- Ne pas transmettre de secrets, données personnelles ou code confidentiel à un service non autorisé.
- Respecter les règles de classification et les politiques de l'organisation.
- Exiger une justification pour les changements touchant sécurité, authentification, autorisations, données ou architecture.
- Vérifier les API, options de configuration et versions dans la documentation officielle lorsque l'exactitude dépend de la version.
- Ne pas inventer une référence, une source, un résultat de commande ou une exécution.
- Distinguer clairement : constat observé, hypothèse, recommandation et élément à confirmer.
- Garder l'humain responsable des décisions de conception, de sécurité et de mise en production.
- Demander confirmation avant toute action destructive, irréversible, coûteuse ou affectant un système partagé.

**Livrable d'une intervention significative :** résumé, fichiers touchés, décisions, tests réellement exécutés, risques résiduels et actions restant à effectuer.
